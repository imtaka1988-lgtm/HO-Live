## 四、房间 ID 规则

当前规则：

```text
已有房间 ID 不自动改名。
删除 12 号房间后，13 号仍然保持 13。
下一次新建房间时，优先补回最小空缺 ID，也就是补回 12。
```

这样做比“删除 12 后立刻把 13 改成 12”更安全。

原因：房间 ID 会关联主播账号、播放源、推流配置、直播回调记录、后台按钮、前台直播间链接。强行改已有房间 ID 容易导致按钮错位、播放源错位、主播账号错位。

重点验收：

```text
1. 删除 12 号房间
2. 再新建房间
3. 新房间应补回 12
4. 房间列表应按 1、2、3、4... 从小到大排列
5. 每行四个按钮必须对应当前行房间
```

## 五、后台手动放视频源

后台手动填 m3u8 / flv 播放源不受直播回调鉴权影响。

你仍然可以按原方式操作：

```text
后台 → 房间 → 填播放源 → 保存 → 前台播放
```

影响范围说明：

```text
后台手动填播放源：不受影响
后台新增房间：不受影响
后台改房间资料：不受影响
用户看直播：不受影响
直播云厂商自动通知开播/关播：需要 key
```

## 六、直播回调接口 key

直播回调接口用于腾讯云/阿里云等直播服务通知网站：某个房间开播或关播。

现在该接口需要 key，防止外部伪造请求乱改房间状态。

服务器环境变量：

```bash
LIVE_CALLBACK_KEY=你自己设置的随机长字符串
```

云厂商回调地址示例：

```text
https://你的域名/api/live/callback?key=同一个随机长字符串
```

如果暂时不使用云直播回调，可以不用管。

如果临时要放开无 key 回调，可以设置：

```bash
LIVE_CALLBACK_ALLOW_UNSIGNED=1
```

正式环境不建议长期放开。

重点验收：

```text
1. OBS 推流后，房间状态是否自动变直播中
2. OBS 停推后，房间状态是否自动变离线
3. 如果没有配置 LIVE_CALLBACK_KEY，回调会被拒绝
4. 后台手动改状态仍然可以使用
```
